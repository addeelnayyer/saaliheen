# Phrases are marked by hand by Admins and never overlap

So that someone can recite without knowing the translation, Quran Analysis tints each Phrase, a run of Words from a place a reciter may start to a place they may stop, in alternating Phrase colours. Admins mark every Phrase by hand in the Passage editor; the pause marks printed in the Quranic text (ۚ ۖ ۗ ۘ ۛ …) are left exactly as printed ([0002](0002-script-specific-quran-text.md)) and are neither imported as Phrases nor kept in step with them. A Word belongs to at most one Phrase, so where the Quran allows a choice of stops (e.g. رَيۡبَ or فِيهِ in 2:2) the Admin picks one. A Phrase may run past the end of an Ayah but never across a Passage, and a Passage shows its Phrases only once every one of its Words is in one, so Admins can publish a Passage half-marked ([0006](0006-admin-edits-to-passages-are-commits.md)) without readers seeing gaps. Like Passage titles, Phrases need no Scholar's approval.

## Considered Options

- Starting from the Uthmani pause marks and letting Admins adjust them: rejected because the marks differ between Uthmani and Indo-Pak, come in strengths (must stop, may stop, better to continue, pairs where only one applies) that do not map onto one start-and-stop run, and would have left Saaliheen's guidance and the printed marks to disagree in ways nobody chose.
- Showing the printed marks alone with no Admin step: rejected for the same reasons, and because the marks never say where to start again.
- Overlapping Phrases, so a choice of stops shows as alternatives and Words between them take a third colour: rejected for now as a harder model, editor and validity rule than readers need to begin with. Revisit if a Scholar asks for alternative stops; it would need Phrases to become a set of possible routes rather than one run per Word.
- Phrases ending at every Ayah end: rejected because many sentences, and so many good places to stop, run across an Ayah's end (e.g. 1:6–7).
