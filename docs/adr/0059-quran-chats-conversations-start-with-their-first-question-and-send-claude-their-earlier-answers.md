# Quran Chat's Conversations start with their first question and send Claude their earlier answers

A signed-in person's questions to Quran Chat and its answers are kept in Conversations, for their Account, so they can come back to them in any browser (#79). Two tables come with `pnpm db:migrate`, through Better Auth's schema like the Reading places' (`src/quran-chat/conversations.ts`): `conversation` (its Account, title, when it was started and last asked in) and `conversationQuestion` (its Conversation, the question, its Language, when it was asked, the answer, whether it was declined). Each is deleted with the row above it, so deleting an Account deletes its Conversations and every question in them.

**A Conversation starts with its first question.** There is no call to make an empty one: `POST /api/v1/questions` without `conversation` starts one, titled by the question (its first 80 characters, on one line); with `conversation` it continues that one, which moves to the top of the list. Either way the answer's first event names it, `{ "type": "conversation", "id" }`, so the page or app asking knows which Conversation it is in before any text arrives. A `conversation` that is not one of the Account's, whether another Account's, deleted, or never made, is not found (404) before Claude is asked, so no one learns which ids exist.

**The question is kept when asked; its answer when whole.** The question is written as the stream starts, its answer as it ends: the text as written, or the decline with `declined` set. An answer that fails, is refused, or is cut off by the person moving on is never kept, and the question stays with no answer, which the page shows as such. A half-written answer is never kept as if it were whole.

**Claude is sent the earlier exchanges, without their sources.** A continued Conversation's last ten answered questions, declined ones left out, go before the new question as earlier user and assistant turns; sources are searched for the new question only, and the system prompt says the earlier turns are only for understanding what the question refers to. A follow-up such as "Where did he travel?" is then understood, while every answer still rests on sources found for it. Ten bounds what a long Conversation costs per question.

`GET /api/v1/conversations` lists the Account's Conversations, the one asked in most recently first; `GET /api/v1/conversations/<id>` reopens one with its questions in order; `DELETE` deletes it (204). The website lists them beneath the question, to reopen or delete, with a New Conversation button; it keeps the Conversation open only in the page, not its address. A question asked in a Conversation deleted in another browser meanwhile is not lost: the page says so, empties, and keeps the question in its box, so asking it again starts a new Conversation; while a Conversation is being reopened, no question can be asked, lest it go to the one open before.
